# صنعة — Manufacturing Operating System

**صنعة** مش برنامج حسابات مصنع ملابس. صنعة **نظام تشغيل للتصنيع** يخدم أي نشاط إنتاجي قائم على
خامات + عمليات + عمال + مخزون + أوامر إنتاج: ملابس، شنط، أحذية، مفروشات، إكسسوارات، أغذية.

المبدأ الحاكم: **سجّل مرة واحدة، والنظام يحسب كل حاجة.** كل حركة بتسجلها بتظهر في المخزون والتكلفة
والربحية ورصيد العميل ومستحقات العامل والخزنة في نفس اللحظة.

الوثائق الكاملة في [`docs/`](docs/): [الرؤية والمتطلبات](docs/prd.md) ·
[المعمارية](docs/architecture.md) · [نظام التصميم](docs/design-system.md) ·
[جهات التعامل](docs/parties.md) · [خطة الموديولات](docs/roadmap.md).

## التشغيل محلياً

```bash
npm install
npm run dev
```

افتح العنوان اللي هيظهر (الافتراضي `http://127.0.0.1:43127`).

- **اعمل مصنعك**: تختار نشاط المصنع، والنظام يجهّز الوحدات والفئات والخامات والعمليات المناسبة.
- **رجّع نسخة احتياطية**: ملف JSON من زرار التنزيل جوه الإعدادات.
- **دخول تجريبي**: مصنع بداتا جاهزة، بثلاث أدوار.

### الأدوار

| الدور | يقدر يعمل إيه |
| --- | --- |
| صاحب المصنع | كل حاجة. هو بس اللي يمسح، أو يرجّع نسخة، أو يضيف موظفين، أو يشوف سجل التعديلات |
| محاسب | يشوف ويسجل ويعدّل الحسابات، ميمسحش |
| مشرف | الإنتاج والمخزن والعمال والحضور. مبيشوفش العملاء ولا الخزينة ولا التحصيلات |

من الموبايل: في Safari أو Chrome اختَر **Add to Home Screen** عشان يتثبت باسم صنعة وأيقونتها.

## اللي شغال دلوقتي

**نواة التصنيع**
- **المنتجات**: كل منتج بكوده وفئته ووحدته وسعر بيعه.
- **قائمة الخامات (BOM)**: كمية كل خامة في القطعة + نسبة الهالك، والتكلفة بتتحسب لوحدها.
- **مسار العمليات (Routing)**: خطوات التصنيع بالترتيب، سعر القطعة والزمن المعياري لكل خطوة.
- **تكلفة القطعة** = خامات (بعد الهالك) + أجور العمليات + أوفرهيد. مفيش رقم تكلفة بيتكتب بالإيد.
- **المخزن**: الرصيد **محسوب من دفتر الحركات** ومش مخزّن — تدوس على أي خامة تشوف الحركات اللي كوّنته.
- **ذكاء إعادة الطلب**: متوسط الاستهلاك اليومي، أيام التغطية، وكمية الشراء المقترحة.
- **أمر الإنتاج بالتفصيل**: احتياج الخامات، صرفها من المخزن بضغطة، متابعة المراحل بالكميات
  (سليم/تالف)، اكتشاف الاختناق، والتكلفة **المتوقعة مقابل الفعلية**.

**جهات التعامل**
- **سجل واحد لكل جهة**: نفس السجل يكون عميل وتاجر ومورّد في نفس الوقت — مفيش جداول منفصلة.
- **بروفايل حيّ**: الملف المالي والتجاري والإنتاجي، خط زمني بكل حركة حصلت، كشف حساب، ائتمان.
- **سكور بتفسيره**: كل مكوّن بيقول الرقم اللي اتبنى عليه، ولو البيانات مش كفاية يقولها صريح.
- **تصنيف تلقائي**: استراتيجي، بينمو، بيقل، متوقف، معرّض للفقد، بيدفع بسرعة أو بيتأخر.
- **حد الائتمان**: تحذير بالمبلغ بالظبط قبل أي توريد بيعدّي المتاح، بموافقة صريحة.
- **متابعة**: تسجيل مكالمة أو زيارة، مهمة متابعة تتفتح لوحدها، وملاحظات داخلية العميل مبيشوفهاش.
- **منع التكرار والدمج**: كشف السجلات المتشابهة، والدمج بينقل الحركات ويأرشف المكرر — مش بيمسح.

**المالية والتشغيل**
- أوامر الإنتاج: ترقيم `SN-####`، خط الإنتاج، نسبة الإنجاز، وحالات مكتمل / قيد التنفيذ / متأخر / متوقف.
- التوريد والتحصيل: كشف حساب برصيد متحرك، والتحصيل من أقدم توريد (FIFO).
- التحويل البنكي والإنستاباي والمحفظة: صورة إجبارية، ويفضل «مستني تأكيد» لحد ما الفلوس توصل.
- زرار واتساب برسالة تذكير جاهزة بالمبلغ.
- بنود التكلفة والدفعات والموردين.
- عمال: يومية / شهري / قطعة، حضور جماعي، سلف وخصومات، والأجر بالقطعة بيتربط بأمر الإنتاج والعملية.
- خزينة: رصيد كل حساب، أرباح وخسائر لأي فترة، وكل اللي عليك.
- موظفين وسجل تعديلات لصاحب المصنع.

## ربط Supabase (لما تكون جاهز)

1. في إعدادات المشروع على Supabase، في **Exposed schemas**، ضيف `factory`.
2. انسخ `.env.example` إلى `.env` وحط `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`.
3. في Authentication → Redirect URLs، حط رابط التطبيق بعد ما يترفع.
4. نفّذ `supabase/schema.sql` (الأساس)، وبعدها `supabase/migrations/0002_manufacturing_core.sql`
   ثم `supabase/migrations/0003_parties.sql` بالترتيب.
5. لو المصنع جوه مشروع الجيم الحالي (`ufljewjhajhjcxeyocrk`)، الجداول بتتعمل في schema اسمها `factory`.
   جداول الجيم متتلمستش.

كل Migration **إضافية ومتوافقة مع الخلف**: مفيش `DROP` ولا `RENAME`، والأعمدة الجديدة على الجداول
القائمة كلها nullable. من غير الخطوة دي التطبيق يفضل يشتغل بالدفتر المحلي على الجهاز.
