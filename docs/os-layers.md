# صنعة — الطبقات السبعة: من ERP لـ Operating System

الرؤية الأخيرة (٧٠ بند) مش قائمة شاشات؛ دي **طبقات**. والبند الواحد ممكن يبقى سهل
أو مستحيل حسب حاجة واحدة بس: **هل البيانات اللي بيحتاجها بتتسجّل في النظام أصلًا؟**

فالمستند ده بيرتّب الـ٧٠ بند على الطبقات السبعة، وبيقول لكل بند:

- **الحالة** — ✅ موجود · ◐ جزئي (الأساس موجود ومحتاج طبقة فوقه) · ○ محتاج بيانات لسه مش بتتسجّل
- **محتاج إيه** — بالظبط البيانات أو الجدول الناقص
- **الموديول** — مكانه في [خطة البناء](./roadmap.md)

القاعدة الحاكمة اللي اتفقنا عليها: **كل موديول مربوط بنفس Core Data Model**.
العميل والمنتج والخامة وأمر الإنتاج والعامل والمورّد والمخزن والفاتورة والتحصيل والربح
مش أنظمة منفصلة؛ كلهم نفس شبكة البيانات. وعشان كده الطبقات دي بتتراكم: كل موديول
بيغذّي اللي بعده بدل ما يبقى Dashboard شكله حلو.

## القراءة المهمة في الجدول ده

١) **٤٠٪ من البنود مش محتاجة موديول جديد، محتاجة بيانات جديدة تتسجّل.**
ماكينات وتوقف وطاقة كهربائية وفحوصات جودة — دي مش حسابات ناقصة، دي حركات المصنع
لسه مش بيسجّلها. وأي Dashboard لـOEE قبل تسجيل التوقف هيبقى رقم مخترع.

٢) **البنود الرخيصة دلوقتي هي اللي بياناتها موجودة ومحتاجة تجميع بس:**
لوحة الإدارة، الإيجاز اليومي، الإدارة بالاستثناء (٥١–٥٣)، التدفق النقدي وأعمار
المستحقات (٢٨–٣٠)، وإنتاجية العامل (١٢). دي الترتيب المنطقي بعد M-O1.

٣) **الطبقات بتتراكم بترتيب واحد:** تسجيل → ضبط → تحليل → ذكاء → أتمتة → توقع.
مينفعش نعمل «توقع» على طبقة تسجيل ناقصة، والنتيجة هتبقى أرقام واثقة وغلط.

٤) **كل بند ناقص بيانات بيتكتب في الواجهة كده بالنص**، مش بيتخمّن. نفس القاعدة اللي
ماشية في السكور وفي الجدولة: الأمر اللي مالهوش زمن معياري بيظهر في «برّه الجدولة»
بسببه، مش بزمن مفترض.
