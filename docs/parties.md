# صنعة — جهات التعامل (Parties Core)

> صنعة مش Factory ERP. صنعة **Central Business & Relationship Management System for Manufacturing**:
> كل شخص أو جهة بتتعامل مع المصنع بتبقى **كيان مستقل له Profile حي**، وكل تعامل حصل معاه
> بيتجمع لوحده في Timeline وحسابات وتحليلات وسكور.

---

## 1. قرار معماري (ADR-001): جدول واحد للجهات، والأدوار فوقه

**القرار:** مفيش جداول منفصلة لـ"عملاء" و"تجار" و"موردين". فيه **`parties`** واحد،
وفوقه **`party_roles`** (علاقة متعدد-لمتعدد مع قائمة أدوار محكومة).

**ليه:**
- نفس الشركة ممكن تكون **عميل + مورد** في نفس الوقت (بتشتري منك منتجات وبتوردلك تغليف).
  بجدولين منفصلين بتبقى سجلين، وتاريخ العلاقة بيتقسم، والرصيد بيتفرّق.
- المندوب ممكن يكون **مندوب مبيعات + عميل**. الورشة ممكن تكون **ورشة خارجية + مورد خامات**.
- البحث الموحّد والدمج ومنع التكرار كلهم بيحتاجوا مكان واحد للحقيقة.

**النتيجة العملية:**

```
parties (id, kind: person|company, name, tax_id, phone, ...)
   └── party_roles (party_id, role)        ← عميل، مورد، تاجر، ورشة، مندوب...
   └── party_contacts (شخص جوه شركة)
   └── party_addresses (رئيسي، مخزن، فوترة، شحن، فرع، مصنع)
   └── party_communications (مكالمة، واتساب، إيميل، زيارة، ملاحظة)
   └── party_tasks (متابعة بميعاد ومسؤول)
```

كل الحركات (توريدات، تحصيلات، أوامر إنتاج، مشتريات) بتشير لـ**party_id واحد**،
فالـTimeline والحسابات والسكور بيتجمعوا لوحدهم.

**التوافق مع الخلف:** جدول `clients` القديم فضل زي ما هو وبيشير لـ`party_id`.
في التطبيق، كل عميل قديم اتحوّل لـParty بدور "عميل" **بنفس الـid**، فكل التوريدات
والتحصيلات والأوامر القديمة فضلت مربوطة من غير أي تحويل.

## 2. الأدوار (Roles)

| الدور | الوصف |
|---|---|
| عميل | بيشتري منتجات |
| تاجر | بيشتري بغرض إعادة البيع |
| تاجر جملة / تاجر تجزئة | تصنيف تجاري يأثر على قائمة الأسعار |
| مورّد | بيورّد خامات أو خدمات |
| موزّع / وكيل | بيغطي منطقة أو خط منتجات |
| ورشة خارجية | بينفّذ عمليات تشغيل خارجي |
| مندوب مبيعات / مندوب تحصيل | موظف ميداني له Target وأداء |
| شريك / مقدم خدمة / شحن / صيانة / مقاول | باقي جهات التعامل |
| جهة أخرى | أي حاجة تانية |

الجهة ممكن يكون لها **أكتر من دور**، والبروفايل بيعرض التابات المناسبة لكل دور.

---

## 3. Universal Profile

أي جهة بتفتح على نفس الهيكل، والمحتوى بيختلف حسب الدور:

| القسم | المحتوى |
|---|---|
| **نظرة عامة (360)** | مالي · تجاري · إنتاج · علاقة · ذكاء — كله في شاشة واحدة |
| **الخط الزمني** | كل حدث حصل مع الجهة بترتيب زمني |
| **الحساب** | كشف حساب برصيد متحرك، والمتأخر، والائتمان |
| **جهات الاتصال والعناوين** | أشخاص الشركة وأدوارهم، والعناوين بأنواعها |
| **التواصل والمهام** | مكالمات وواتساب وزيارات، ومهام متابعة بميعاد ومسؤول |
| **التحليلات** | المنتجات المفضّلة، نمط الشراء، الطلب المتوقع |
| **السكور** | الدرجة بتفاصيلها و**ليه** طلعت كده |

---

## 4. السكور — قواعد الصدق

السكور **محسوب من بيانات المصنع بس**، ومينفعش يتخمّن:

1. كل مكوّن في السكور له **مصدر بيانات واضح** ومعروض للمستخدم تحت عنوان **ليه؟**.
2. لو مفيش تاريخ كافي (أقل من توريدين مثلًا)، النظام بيقول **"البيانات لسه مش كفاية"**
   ومبيطلّعش رقم مخترع.
3. مكوّنات سكور العميل: الالتزام بالسداد · حجم التعامل · النمو · الربحية · المخاطر.
4. مكوّنات سكور المورّد: حجم التوريد · الالتزام بالسداد المتبادل · استمرارية التعامل.
   (الجودة ووقت التوريد هيدخلوا مع موديول المشتريات والجودة — مش هيتخمّنوا قبلها.)

---

## 5. الائتمان (Credit)

لكل جهة: **حد ائتمان** و**مهلة سداد بالأيام**.

```
التعرّض الحالي (Exposure) = إجمالي التوريدات − التحصيلات المؤكدة
الائتمان المتاح          = حد الائتمان − التعرّض الحالي
```

عند تسجيل توريد بيعدّي المتاح، النظام **بيحذّر بالرقم بالظبط** وبيطلب تأكيد،
ومبيمنعش صاحب المصنع — بس بيسجّل القرار.

---

## 6. منع التكرار والدمج

قبل حفظ جهة جديدة، النظام بيدوّر على: **الموبايل · الرقم الضريبي · الاسم**.
لو لقى شبيه بيعرضه ويسأل: تستخدم الموجود ولا تكمّل جديد؟
ولو اتعمل تكرار بالغلط، فيه **دمج** بيحوّل كل الحركات والاتصالات والمهام للسجل الأساسي
وبيسجّل العملية في Audit Log. **مفيش حذف** — الدمج بيأرشف السجل المكرر.

---

## 7. اللي في الموديول ده واللي بعده

**اتنفّذ دلوقتي (M-P1):** الـParties Core بالأدوار، البروفايل الموحّد بكل تاباته،
الخط الزمني، جهات الاتصال والعناوين، التواصل والمهام، التاجات والتصنيف التلقائي،
سكور العميل والمورّد بتفسيره، الائتمان، منع التكرار والدمج، مركز الجهات بلوحة المحفظة
وتركيز الإيراد و"مين أركز عليه النهارده"، وربط المورّد ببنود التكلفة.

**اللي بعده:** بورتال العميل والمورّد · الشكاوى والمرتجعات · قوائم الأسعار والعقود ·
بروفايل الورشة الخارجية بأعماله · أداء المندوبين مقابل التارجت · الخريطة الجغرافية ·
الـCohort والـCLV · Relationship Graph · المساعد الذكي فوق كل ده.
