# صنعة — المعمارية (Architecture)

## 1. الوضع الحالي (Existing Foundation)

| الطبقة | الحالي |
|---|---|
| Frontend | Vite 8 + React 19 + TypeScript + Tailwind v4 + PWA (vite-plugin-pwa) |
| State | `FactoryProvider` — متجر محلي على `localStorage` (`factory-ledger.v1`) مع `migrate()` |
| Backend المستهدف | Supabase — schema `factory`، RLS على كل جدول، مفاتيح مركّبة `(factory_id, id)` |
| Storage | bucket `factory-receipts` (حد أقصى 5MB) |
| Auth | Supabase Auth + Members + Invites |

**قاعدة مقدّسة:** الجداول والـ Views والـ Functions الموجودة في `supabase/schema.sql`
**لا تتغير ولا تُحذف**. أي إضافة تيجي في Migration جديدة **إضافية (Additive)** فقط.

---

## 2. الطبقات

```
┌──────────────────────────────────────────────┐
│  UI Layer — Pages + shadcn-style primitives  │  ← عرض فقط، لا منطق أعمال
├──────────────────────────────────────────────┤
│  Selectors (compute.ts) — دوال نقية          │  ← كل الأرصدة والتكاليف تُحسب هنا
├──────────────────────────────────────────────┤
│  Store / Data Access (context.tsx → API)     │  ← تحقق الصلاحيات + Audit
├──────────────────────────────────────────────┤
│  Database — Postgres + RLS + RPC Functions   │  ← مصدر الحقيقة والصلاحيات الفعلية
└──────────────────────────────────────────────┘
```

- **UI لا تحسب.** أي رقم بيجي من `compute.ts` أو من View في الداتابيز.
- **الصلاحيات في مكانين**: الواجهة تخفّي، والداتابيز تمنع. الواجهة وحدها **لا تكفي**.

---

## 3. مبادئ قاعدة البيانات

1. **Multi-tenant**: كل جدول فيه `factory_id NOT NULL`، ومفتاح أساسي مركّب `(factory_id, id)`،
   وكل علاقة خارجية تشير للمفتاح المركّب — فمستحيل سطر يشير لسطر في مصنع تاني.
2. **RLS على كل جدول بلا استثناء**، مبنية على عضوية المستخدم في المصنع + دوره.
3. **Enums محكومة** للحالات (status) — مش نصوص حرة.
4. **الأرصدة Views**: `factory.v_stock_balance`, `v_client_balance`, `v_account_balance`,
   `v_worker_balance`, `v_order_cost`. الجداول تخزّن **حركات** فقط.
5. **Soft state بدل الحذف**: `cancelled_at`, `cancelled_by`, `cancel_reason`.
6. **Idempotency**: كل Mutation جاية من الموبايل معاها `client_op_id` فريد،
   عشان المزامنة بعد انقطاع النت ما تكرّرش الحركة.
7. **Append-only Ledgers**: `stock_movements`, `audit_log` — إدخال فقط. التصحيح بحركة عكسية.

## 4. دفتر المخزون (Inventory Ledger) — قلب النظام

جدول واحد `factory.stock_movements` بيغطي كل حركة:

| الحقل | الوصف |
|---|---|
| `item_type` | `material` \| `product` |
| `item_id` | الخامة أو المنتج |
| `warehouse_id` | المخزن |
| `batch_id` | الدفعة/الرول (اختياري) |
| `kind` | `purchase` \| `issue` \| `return` \| `adjust` \| `waste` \| `receipt_fg` \| `delivery` \| `transfer_in` \| `transfer_out` |
| `qty` | موجب دخول، سالب خروج |
| `unit_cost` | تكلفة الوحدة وقت الحركة |
| `ref_type` / `ref_id` | المصدر: أمر شراء، أمر إنتاج، تسليم… |

**الرصيد = SUM(qty)** لكل (مصنع، صنف، مخزن). مفيش عمود `current_stock` في أي مكان.
ده اللي بيخلّي الجرد قابل للتفسير: تدوس على الرصيد تشوف الحركات اللي كوّنته.

## 5. حساب التكلفة

```
تكلفة أمر الإنتاج المتوقعة = Σ (كمية BOM × (1 + هالك%) × متوسط تكلفة الخامة)
                            + Σ (كمية × سعر العملية)
                            + أوفرهيد موزّع

التكلفة الفعلية            = Σ (الخامات المصروفة فعليًا × تكلفتها وقت الصرف)
                            + الأجور المسجّلة على الأمر
                            + التشغيل الخارجي
                            + أوفرهيد موزّع
```

**الأوفرهيد** يُوزَّع بطريقة يختارها المصنع: بالقطعة، بساعة العمل، بنسبة من التكلفة المباشرة.
**الخامات تدخل التكلفة وقت الاستهلاك — مش وقت الشراء.** الشراء حركة مخزون، مش مصروف.

---

## 6. المزامنة والعمل بدون إنترنت

- طابور محلي `outbox` بالعمليات، كل واحدة بـ `client_op_id`.
- عند رجوع الشبكة: إرسال بالترتيب، والسيرفر يرفض المكرر بالـ id.
- التعارض (Concurrency) يُحل بـ optimistic locking على `updated_at` مع رسالة واضحة للمستخدم.

---

## 7. الأمان

- Supabase Auth + RLS + Tenant Isolation + RBAC + Secure Storage + Audit Log.
- التحقق من المدخلات على الطرفين، والاعتماد النهائي على **Server-side validation**.
- الأسرار لا تُخزَّن في الواجهة إطلاقًا.
- أي OCR أو استخراج تلقائي **لا يُحفَظ بدون تأكيد المستخدم**.
- رسائل الواتساب: Opt-in + Template + Permission + Logging. **مفيش إرسال تلقائي صامت.**
- الاسترجاع (Restore): معاينة → تحقق → تأكيد → تنفيذ → تسجيل في الـ Audit. لـ **Owner فقط**.

## 8. استراتيجية الترحيلات (Migrations)

| الملف | المحتوى |
|---|---|
| `supabase/schema.sql` | الأساس الحالي (يُعتبر `0001`) — **لا يُعدَّل** |
| `supabase/migrations/0002_manufacturing_core.sql` | المنتجات، BOM، العمليات، الخامات، المخازن، دفتر المخزون |
| `0003_purchasing.sql` | الموردون ودورة الشراء |
| `0004_quality.sql` | الفحص والعيوب |
| `0005_planning.sql` | الجدولة والطاقة والماكينات |

قواعد كل Migration:
- إضافة جداول/أعمدة فقط. أي عمود جديد على جدول قائم لازم يكون `NULL` أو له `DEFAULT`.
- لا `DROP` ولا `RENAME` لأي شيء تستخدمه نسخة منشورة.
- كل Migration تنتهي بتفعيل RLS وسياساتها على الجداول الجديدة.
- أي تغيير سلوكي يتوثّق في نفس الملف كتعليق بالسبب.
