# الرفع على السيرفر والدومين

السيرفر: Ubuntu 24.04 عليه CloudPanel — `187.127.79.131`.

صنعة النهارده **تطبيق ثابت**: البناء بيطلع ملفات HTML و JS و CSS، مافيش عملية
شغّالة على السيرفر ولا بورت بيسمع. يعني الرفع بسيط، ومافيش حاجة تقع في نص
الليل. بس خُد بالك من نتيجة واحدة مهمة قبل ما تبدأ:

> **البيانات لسه في المتصفح.** كل مصنع متخزّن في `localStorage` على الجهاز
> اللي بيفتح منه. يعني لو فتحت من لابتوبك ومن موبايلك، دول **مصنعين
> مختلفين** مش نفس المصنع. الرفع على الدومين بيخلي النظام متاح من أي مكان،
> مش بيخلي البيانات مشتركة. المشاركة دي هي بالظبط شغلة Supabase —
> [supabase.md](./supabase.md).

## ١) الدومين يشاور على السيرفر

من مكان تسجيل الدومين، اعمل سجلّين:

| النوع | الاسم | القيمة |
|---|---|---|
| A | `@` (أو الدومين نفسه) | `187.127.79.131` |
| A | `www` | `187.127.79.131` |

استنى لحد ما ينتشر، واتأكد:

```bash
dig +short YOUR-DOMAIN.com
# لازم يطلع 187.127.79.131
```

ماتكملش قبل السطر ده يطلع صح — شهادة Let's Encrypt بتفشل لو الدومين لسه
مش واصل للسيرفر.

---

## ٢) الموقع في CloudPanel

لوحة CloudPanel على `https://187.127.79.131:8443`.

**Sites → Add Site → Create a Static Site**

| الخانة | تحط إيه |
|---|---|
| Domain Name | الدومين بتاعك |
| Site User | `sanaa` |
| Site User Password | كلمة سر قوية — احفظها، السكربت مش محتاجها بس إنت محتاجها |

**اختار Static Site مش Node.js.** النوع التاني بيجهّز عملية Node و reverse
proxy — وده مالهوش لازمة هنا، وبيزوّد حاجة تتعطّل من غير فايدة.

المسار اللي بيتعمل: `/home/sanaa/htdocs/YOUR-DOMAIN.com` — ده اللي السكربت
بيرفع عليه.

---

## ٣) الشهادة

**Sites → الموقع → SSL/TLS → New Let's Encrypt Certificate**

اختار الدومين و`www`، واعمل Create. CloudPanel بيجدّدها لوحده بعد كده.

## ٤) إعداد نجينكس للتطبيق

دي الخطوة الوحيدة اللي لو نسيتها النظام هيبان إنه شغّال وهو مكسور، فمهم
تعملها.

الأول اطبع الإعداد وفيه بيانات موقعك محطوطة:

```bash
DOMAIN=YOUR-DOMAIN.com SITE_USER=sanaa ./deploy/vhost.sh
```

وبعدين **Sites → الموقع → Vhost**، وحُط الناتج جوه بلوك `server` اللي على
٤٤٣، وشيل أي `location /` قديم.

(الأصل اللي بيتقرأ منه هو
[`deploy/cloudpanel-vhost.conf`](../deploy/cloudpanel-vhost.conf) — لو عايز
تشوفه بالـplaceholders. السكربت بيطبع بس ومابيكتبش، لأن الـvhost في
CloudPanel بيتعدّل من اللوحة، واللوحة هي اللي بتعمل `nginx -t` وترفض الحفظ
لو فيه غلطة؛ وأي تعديل بإيدينا على الملف من ورا اللوحة ممكن يتكتب فوقه.)

**ليه ضروري:** مسارات صنعة (`/orders`، `/health`) مش ملفات على الديسك.
من غير سطر `try_files`، الصفحة الرئيسية بتفتح عادي — وأول ما حد يعمل
Refresh وهو جوه أي شاشة، ياخد ٤٠٤. والبلوك التاني المهم هو منع كاش
`sw.js`، لأن سيرفس ووركر متكاش معناه مستخدم قاعد على نسخة قديمة من
النظام ومش عارف.

بعد الحفظ، CloudPanel بيعمل `nginx -t` لوحده ويرفض الحفظ لو فيه غلطة.

## ٥) الرفع

من جهازك (مش من السيرفر):

```bash
DOMAIN=YOUR-DOMAIN.com \
SITE_USER=sanaa \
SSH_TARGET=root@187.127.79.131 \
./deploy/deploy.sh
```

السكربت بيبني محليًا، بيرفع نسخة جانبية، وبعدين **بيبدّل** المجلد بحركة
واحدة. التبديل ده مش تفاصيل: لو كتبنا فوق القديم، فيه ثانية أو اتنين
الـ`index.html` الجديد بيطلب ملفات لسه ماوصلتش، واللي فاتح النظام في
اللحظة دي بيشوف شاشة بيضا. وبيسيب آخر نسختين للرجوع السريع لو حاجة طلعت
غلط.

وفي الآخر بيتأكد بنفسه إن `/` و`/orders` الاتنين بيردوا ٢٠٠، وبيفشل لو لأ.

### البناء محليًا مش على السيرفر

بقصد. `vite build` بياخد حوالي ٢ جيجا رام في الذروة، والسيرفر ٤ جيجا
وعليه CloudPanel وقواعد بياناته. البناء على السيرفر ممكن يتقتل في النص أو
يبطّل المواقع التانية وهو بيبني.

لو مضطر تبني على السيرفر نفسه (مافيش عندك Node محليًا مثلًا)، نفس السكربت
بيشتغل هناك:

```bash
DOMAIN=YOUR-DOMAIN.com SITE_USER=sanaa SSH_TARGET=local ./deploy/deploy.sh
```

وقتها اعمل swap الأول عشان البناء مايتقتلش — والسكربت بيحذّرك لو مش موجود:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```

## ٦) اتأكد بنفسك

```bash
curl -I https://YOUR-DOMAIN.com/            # 200
curl -I https://YOUR-DOMAIN.com/orders      # 200 — لو 404 يبقى try_files ناقص
curl -I https://YOUR-DOMAIN.com/sw.js       # لازم Cache-Control: no-store
curl -sI https://YOUR-DOMAIN.com/assets/ -o /dev/null -w '%{http_code}\n'
```

وفي المتصفح: افتح الدومين، اضغط **دخول تجريبي → صاحب المصنع**، واتأكد إن
مصنع النور فتح والشريط الأصفر بان. وبعدها اعمل Refresh وإنت جوه
`/orders` — لازم تفضل في نفس الشاشة.

النسخة المبنية نفسها متأكد منها محليًا قبل ما توصل للسيرفر:
`node tests/prod-serve.mjs` بيقدّم `dist/` بنفس قواعد نجينكس اللي فوق
(٢٣ تأكيد) — بيفتح النظام، بيدخل تجريبي، بيعمل Refresh على مسار جوّة،
وبيتأكد إن الخط العربي طالع من الناتج نفسه مش من نت برّاني.

## ٧) حاجتين أمان على السيرفر نفسه

مش جزء من صنعة، بس ليها لازمة لأن اللوحة دي بتتحكم في السيرفر كله:

1. **لوحة CloudPanel على ٨٤٤٣ مفتوحة للدنيا كلها دلوقتي.** قفلها على
   IP بيتك أو المكتب — CloudPanel فيه Admin Area → Security → IP Address
   Restriction. أو من الفايروول:
   ```bash
   ufw allow from YOUR.IP.HERE to any port 8443 proto tcp
   ufw deny 8443
   ```
2. **الدخول بـroot بكلمة سر.** حوّله لمفتاح:
   ```bash
   ssh-copy-id root@187.127.79.131
   # وبعد ما تتأكد إن المفتاح بيدخل:
   # /etc/ssh/sshd_config → PasswordAuthentication no
   systemctl reload ssh
   ```
   ده كمان اللي بيخلّي `deploy.sh` يشتغل من غير ما يسألك كلمة السر كل مرة.
